# TurnScope 0.2.0

Released 2026-08-31.

TurnScope 0.2 adds streaming ingestion and context construction, explicit chat-format adapters,
and bounded-state implementations of the built-in window policies while preserving the v0.1 API.

## Highlights

- JSONL inputs can be consumed one physical line at a time with `iter_conversations()`,
  `iter_path()`, `iter_adapted_jsonl()`, and `iter_adapted_path()`. `ContextBuilder.iter_build()`
  can emit windows without materializing the input conversation or output list.
- Strict OpenAI, Anthropic, and ShareGPT adapters preserve supported text semantics, create
  deterministic fallback IDs and timestamps, report omitted field names, and reject conflicting
  aliases or unrepresentable multimodal/tool-use semantics with located errors.
- `TokenCounter` is a runtime-checkable protocol. The release includes deterministic
  `WhitespaceTokenCounter` and `Utf8ByteTokenCounter` implementations and validates custom
  counter results consistently.
- Built-in turn, token-budget, reply-chain, and chronological time policies use incremental
  state and output-sensitive algorithms. Duplicate-ID auditing no longer rescans prior IDs.
- Strict JSON handling now rejects duplicate keys, non-finite or overflowing numbers, malformed
  Unicode, and adapter JSONL errors with their physical line locations.
- Reproducible data generation and builder benchmark scripts are included together with an
  explicit complexity analysis and randomized equivalence tests.

## Compatibility and migration

No data migration is required. `ContextBuilder.build()`, native list-returning loaders,
`whitespace_tokens`, the existing CLI commands, policy-selection semantics, and v0.1 custom
`WindowPolicy.select` implementations remain supported. The compatibility path for a custom
policy still receives the complete prior sequence, so its time and memory behavior remains
policy-defined.

The new iterators are single-pass. A malformed later record or an unknown requested target can
be reported after earlier values have already been yielded. Callers that require all-or-nothing
behavior should materialize the iterator before performing side effects.

## Verification

The release candidate passed 180 tests with 97.43% branch coverage. Ruff checking and formatting,
strict mypy, source/wheel builds, and an isolated Python 3.12 wheel smoke test also passed. The
checked benchmark and generator are reproducibility tools; wall-clock results are machine-local
and are not a throughput guarantee.

## Known boundaries

- Standard JSON arrays are materialized; use JSONL for line-streamed corpora. One JSONL line still
  contains one complete conversation value.
- `WhitespaceTokenCounter` and `Utf8ByteTokenCounter` are deterministic estimates, not model
  tokenizers. Supply an exact model-specific counter when token parity is required.
- Out-of-order timestamps make `TimeWindowPolicy` fall back to prefix scans to preserve v0.1
  semantics. The time policy also retains prior messages so that fallback remains correct.
- `Auditor.audit()` consumes input once, but its report retains all findings. Adapter support is
  deliberately text-only and fails rather than silently dropping unsupported execution semantics.
